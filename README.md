# requirements-wms-receiving

## 1. Цель проекта
 
**Проблема:** процесс фиксации факта приёмки товара и обработки расхождений между кладовщиком, старшим смены, оператором 1С и закупщиком - полностью бумажный. Это приводит к трём конкретным последствиям:
 
1. **Потеря данных о расхождениях.** 30–40% выявленных расхождений не доходят до 1С или доходят без деталей
2. **Задержка информирования закупщиков.** Закупщик узнаёт о недопоставке через 2–5 дней, когда фура уже вернулась в регион поставщика. Успешность претензий ~60%, оценочные потери — 200–400 тыс. руб./мес.
3. **Двойной ввод и ручная передача документов.** Кладовщик пишет на бумаге, курьер везёт в офис, оператор 1С перепечатывает. Оператор тратит ~24 ч/нед на перевод бумаги в цифру, при этом теряя контекст.
**Результат для бизнеса:** модуль «Приёмка+» должен обеспечить **структурированную цифровую фиксацию факта приёмки и расхождений в момент их обнаружения** на ТСД, **автоматическое формирование акта ТОРГ-2**, **передачу данных в 1С без повторного ввода** и **уведомление закупщика в пределах 30 минут** после утверждения расхождения.

Целевые метрики (из Vision & Scope, BG-01–BG-05):
 
| Метрика | Текущее | Целевое |
|---|---|---|
| Медиана «завершение приёмки → отражение в 1С» | 2,5 сут | ≤ 4 ч |
| Доля расхождений, дошедших до 1С с деталями и фото | ~60% | ≥ 95% |
| Успешность претензий | ~60% | ≥ 90% |
| Часы оператора 1С на приёмку в неделю | ~24 ч | ≤ 4 ч |
| Медиана «начало разгрузки → закрытие приёмки» | ~110 мин | ≤ 55 мин |

## 2. Границы процесса
 
### Start Event
 
**Получение модулем «Приёмка+» данных об ожидаемом поступлении из 1С** (webhook или запрос по расписанию на дату поставки).
 
Обоснование: всё, что происходит до этого момента — создание заказа поставщику, подтверждение поставщиком, формирование «Ожидаемого поступления» закупщиком — относится к процессу закупки и остаётся в 1С. «Приёмка+» получает результат этого процесса как входные данные. Более того, автоматизация принятия Транспорта на воротах не входят в данную проработку. В процессе есть места, которые необходимо автоматизировать\изменить, но в данном проекте фокус именно на приемке товаров.

START: Получение «Ожидаемого поступления» из 1С
  │
  ▼
Назначение приёмки приёмщику (старший смены)
  │
  ▼
Физическое прибытие машины → фиксация факта прибытия
  │
  ▼
Идентификация поставки (сканирование / сверка УПД с ОП)
  │
  ▼
Поштучная/попаллетная сверка товара на ТСД
  │
  ▼
Фиксация расхождений с фотографиями (если есть)
  │
  ▼
Утверждение / эскалация расхождений (старший смены → закупщик)
  │
  ▼
Формирование акта ТОРГ-2 (при расхождениях)
  │
  ▼
Подписание акта (приёмщик + старший + водитель или «в одностороннем порядке»)
  │
  ▼
Контроль оператором 1С (при необходимости)
  │
  ▼
Отправка «Поступления товаров» и «Акта о расхождениях» в 1С
  │
  ▼
Отправка фактических «принятых ок» количеств в WMS
  │
  ▼
Уведомление закупщика о расхождениях
  │
  ▼
END: Данные переданы в 1С и WMS, уведомления отправлены
```
 
### End Event
 
**Успешная передача документа «Поступление товаров и услуг» в 1С, регистрация прихода в WMS Alfa Sistem + отправка уведомлений закупщику (при расхождениях).**
 
После этого момента ответственность переходит:
- **1С** — ведение остатков, финансовый учёт, претензионный документооборот;
- **WMS** — размещение товара по ячейкам, дальнейшие складские операции;
- **Закупщик** — претензионная работа с поставщиком (вне модуля в MVP).
