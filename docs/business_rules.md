# Бизнес правила

Правила пронумерованы `BR-##`. Разделены на группы. На эти правила должна ссылаться SRS.

## 1. Идентификация приёмки и партий

**BR-01. Одна физическая поставка = один документ «Приёмка».**  
Одна поставка от одного поставщика по одному «Ожидаемому поступлению» из 1С создаёт ровно один документ приёмки в модуле «Приёмка+». Если поставщик привёз состав от двух ожидаемых поступлений — оформляются две приёмки.

**BR-02. Идентификация SKU.**  
Учёт ведётся по SKU-коду из справочника номенклатуры 1С. Штрихкод EAN — вспомогательный ключ, может отсутствовать для «мелких» позиций.

**BR-03. Партия.**  
Партия определяется по коду партии на упаковке поставщика (если есть) или по дате поступления. Хранится в модуле «Приёмка+»; в WMS Alfa Sistem не передаётся (WMS партии не ведёт).

## 2. Определение расхождений

**BR-04. Порог значимости количественного расхождения.**  
Количественное расхождение по SKU фиксируется, если абсолютное отличие от ожидаемого больше 0 единиц. 

**BR-05. Виды расхождений (номенклатура).**  
Виды расхождений, которые обязан различать модуль:  
- **Недостача:** фактическое количество меньше ожидаемого.  
- **Излишек:** фактическое количество больше ожидаемого.  
- **Пересорт:** поставщик привёз другую номенклатуру вместо заявленной.  
- **Брак:** товар доставлен с повреждениями упаковки или содержимого.  
- **Некомплект:** позиция состоит из нескольких единиц, не все на месте.  
- **Незаявленное:** SKU, отсутствующее в «Ожидаемом поступлении».

**BR-06. Обязательность фотофиксации.**  
Фотофиксация обязательна для расхождений типа **Брак** и **Пересорт**. Минимум 2 фото. Форматы: JPEG/PNG, не менее 1024×768.  
Для расхождений «Недостача» и «Излишек» фото — по желанию (кроме случаев, когда так требует поставщик; настраивается на уровне поставщика).

## 3. Утверждение и эскалации

**BR-07. Порог эскалации на старшего смены.**  
Приёмка с расхождением на сумму > 5% от ожидаемой стоимости поставки или > 3 позиций требует утверждения старшим смены. При меньших расхождениях старший может утвердить одним нажатием после напоминания.

**BR-08. Порог эскалации на закупщика.**  
Расхождение на сумму > 15% ожидаемой стоимости требует уведомления закупщика **до** утверждения (не после). Приёмка ставится «на паузу» до решения закупщика.

**BR-09. Ограничение по времени эскалации.**  
Если решение закупщика не поступило в течение 45 минут — старший смены получает право утвердить приёмку с расхождениями по собственному решению. Правило может быть отключено администратором.

**BR-10. Спорные приёмки.**  
Если старший смены не согласен с расхождением, зафиксированным приёмщиком, он может пометить его как «спорное» с комментарием. Такая приёмка передаётся оператору 1С для решения; отправка в 1С блокируется.

## 4. Формирование ТОРГ-2

**BR-11. Обязательные поля ТОРГ-2.**  
Автоматически формируемый акт ТОРГ-2 должен содержать:  
- реквизиты поставщика и получателя;  
- номер и дата акта;  
- реквизиты «Ожидаемого поступления» и УПД поставщика;  
- перечень SKU с полями «ожидаемое», «фактическое», «отклонение», «квалификация»;  
- ссылки на фото (URL) — только внутренний акт; для распечатки — QR-код с URL;  
- ФИО и должности членов комиссии.

**BR-12. Комиссия ТОРГ-2.**  
По умолчанию в комиссию входят: приёмщик, старший смены, представитель поставщика (водитель). При отсутствии водителя — старший смены + приёмщик + оператор 1С (в этом случае акт помечается «в одностороннем порядке»).

**BR-13. Хранение экземпляров ТОРГ-2.**  
PDF-версия хранится в модуле не менее 5 лет. Бумажная версия — по внутреннему регламенту (у оператора 1С).

## 5. Отправка в 1С

**BR-14. Момент отправки в 1С.**  
Приёмка отправляется в 1С после утверждения старшим смены (без расхождений — сразу, с расхождениями — после закрытия расхождений).  
Приёмка «в одностороннем порядке» (без подписи водителя) отправляется в 1С только после подтверждения оператором 1С.

**BR-15. Повторная отправка при ошибке.**  
При ошибке отправки в 1С (недоступен, отвергнут документ) — приёмка ставится в очередь с backoff-повторами: 1, 5, 15, 60 минут, далее каждый час. После 24 часов — уведомление администратору.

**BR-16. Идемпотентность.**  
Одна и та же приёмка отправляется в 1С не более одного раза. Ключ идемпотентности — внутренний UUID приёмки, передаётся в 1С.

## 6. Уведомления

**BR-17. Уведомление закупщику.**  
При утверждении приёмки с расхождениями закупщику направления отправляется:  
- email со ссылкой на приёмку и PDF ТОРГ-2 во вложении;  
- сообщение в Telegram-канал направления с краткой сводкой.  
Отправка — в течение 30 минут после утверждения.

**BR-18. Уведомление руководителю склада о повторяющихся проблемах.**  
Если по поставщику более 3 расхождений за 30 дней — генерируется отдельное уведомление руководителю склада («поставщик X — 4 расхождения за месяц»).

**BR-19. Тихие часы уведомлений.**  
Telegram-уведомления шлются в интервале 06:00–22:00 по местному времени. В прочее время — накапливаются и уходят одной сводкой в 06:00.

## 7. Права и доступ

**BR-20. Роли.**  
Роли системы: **Приёмщик**, **Старший смены**, **Оператор 1С**, **Закупщик**, **Администратор**, **Руководитель склада**.

**BR-21. Назначение ролей через AD.**  
Роль определяется членством в AD-группе 

**BR-22. Правило «глаза» для закупщика.**  
Закупщик видит расхождения только по своим поставщикам (по атрибуту «Направление» в справочнике поставщиков).

**BR-23. Дежурство старшего смены.**  
В один момент времени должен быть назначен ровно один старший смены. Расписание ведётся администратором и синхронизируется с AD.

## 8. Локализация и юридические аспекты

**BR-24. Язык интерфейса.**  
Все интерфейсы — на русском языке. Английский — только служебные логи для администраторов.

**BR-25. Формат дат и чисел.**  
Даты — ДД.ММ.ГГГГ. Числа — с запятой в качестве десятичного разделителя. Валюта — рубли, знак «₽».

**BR-26. Форма ТОРГ-2.**  
Соответствует утверждённой форме, применяемой в РФ (постановление Госкомстата от 25.12.1998 №132 в актуальной редакции).
