# Ландшафт существующих систем и точки интеграции

Обзор существующих систем организации ООО ПРИНИМАЮ ТОВАРЫ, их ограничений и доступных точек интеграции для модуля «Приёмка+».
## 1. 1С:ERP 2.5.15

### Роль

Учёт закупок, продаж, финансов. В контексте «Приёмка+» используются документы:
- **«Заказ поставщику»** — заказ, размещённый закупщиком у поставщика.
- **«Ожидаемое поступление»** — конкретизация: что и когда приедет.
- **«Поступление товаров и услуг»** — фактическая приёмка. **Именно этот документ должен создавать «Приёмка+»** по итогам приёмки.
- **«Акт о выявленных расхождениях»** — приложение к «Поступлению», описывает расхождения.

### Инфраструктура

- Развёрнута on-prem в собственном ЦОД.
- Сервер приложений 1С + PostgreSQL кластер.
- Веб-интерфейс через 1С:Веб-сервер.
- Регулярное окно обслуживания: ночь 3-го воскресенья месяца, 00:00–06:00.

### API

1С опубликованы HTTP-сервисы (JSON). Список endpoints, доступных для «Приёмка+» (согласовано с 1С-командой):

| Endpoint | Метод | Назначение |
|---|---|---|
| `/hs/sv/api/v1/expected-shipments` | GET | Список ожидаемых поступлений на указанную дату |
| `/hs/sv/api/v1/expected-shipments/{id}` | GET | Детали ожидаемого поступления по ID |
| `/hs/sv/api/v1/goods-receipts` | POST | Создать документ «Поступление товаров и услуг» |
| `/hs/sv/api/v1/discrepancy-acts` | POST | Создать «Акт о расхождениях» |
| `/hs/sv/api/v1/suppliers/{inn}` | GET | Реквизиты поставщика по ИНН |
| `/hs/sv/api/v1/nomenclature/{code}` | GET | Проверка SKU в справочнике |
| `/hs/sv/api/v1/webhooks/expected-shipment` | webhook | Уведомление о создании/изменении ожидаемого поступления (1С шлёт в модуль) |

### Ограничения

- Полезная нагрузка > 5 МБ — таймауты (нужно резать на страницы).
- Максимум 10 параллельных запросов от одного клиента (ограничение 1С).
- Аутентификация: Basic Auth поверх TLS (сертификат внутренней ЦС).
- Простой окна обслуживания — 6 часов раз в месяц; «Приёмка+» должен продолжать работать, помещая ответы в очередь для повторной отправки.


## 2. WMS «Alfa Sistem 4.3»

### Роль

Управление складом: адресное хранение, отбор, отгрузка, инвентаризация. НЕ ведёт полноценный сценарий приёмки с расхождениями.

### Инфраструктура

- On-prem в собственном ЦОД.
- MSSQL + приложение вендора.

### API

SOAP-сервисы (WSDL, XML). С «Приёмка+» согласованы следующие операции:

| Операция | Назначение |
|---|---|
| `GetFreeCells(nomenclatureCode, quantity)` | Запросить свободные ячейки под номенклатуру |
| `ReserveCells(cells)` | Зарезервировать ячейки на приход |
| `RegisterGoodsReceipt(receiptData)` | Зарегистрировать приход в WMS с фактическими количествами |
| `GetCellByCode(cellCode)` | Получить характеристики ячейки |

### Ограничения

- SOAP + WSDL. Требуется прокси-адаптер в «Приёмка+».
- Никаких прямых записей в БД WMS — только через SOAP (условие вендорского контракта).
- Формат передачи количеств — только шт, не поддерживает партии; партии придётся хранить в «Приёмка+».

### Договорённости

- Вендор гарантирует стабильность существующих операций 
- Расширение SOAP API не планируется — работаем с тем, что есть.

## 3. ТСД Zebra TC22

### Характеристики

- Android 11.
- Экран 5", touchscreen.
- 2D сканер (штрихкоды EAN-13, EAN-128, Code-128, DataMatrix).
- Wi-Fi 802.11ac.
- Камера 13 МП (для фото).
- Батарея 3300 мАч (заявлено 12 ч, по факту после года эксплуатации 7–8 ч на смену).
- Работа в перчатках — поддерживается.

### Ограничения

- Перчатки зимой — сложные жесты (свайпы) не подходят, только крупные тапы.
- Освещение в приёмной зоне — среднее; тёмные виды глаза устают быстрее.
- Wi-Fi покрыт вся площадь РЦ, но приёмная зона у ворот — граница; иногда 1–3 минуты без связи.

### Требования к клиенту

- Автономная работа при пропадании связи (буфер локально, синхронизация при восстановлении).
- Минимальные жесты, крупные кнопки.
- Возможность быстро сделать фото (одним касанием).

## 4. Принтеры этикеток Zebra ZT411

- 3 штуки в приёмной зоне.
- Печать по WiFi, драйвер ZPL.
- Используются для этикеток паллет: SSCC, штрихкод, адрес размещения.

### Точки интеграции

- «Приёмка+» отправляет ZPL-команды по TCP (порт 9100).
- Поддерживаемые форматы этикеток — согласованы с руководителем склада.

## 5. ЭДО СБИС «Диадок»

### Роль

Обмен УПД с поставщиками. С ~70% поставщиков электронный УПД, с 30% — бумажный.

### API

REST API «Диадок», JSON. Согласованные операции:

| Endpoint | Назначение |
|---|---|
| `GET /docs/incoming?status=new` | Список входящих документов |
| `GET /docs/{id}` | Тело документа |
| `POST /docs/reply` | Ответный документ (в MVP не используется, планируется на R2) |

### Ограничения

- ЭП сотрудников уже настроена на серверах СБИС.
- Полная автоматизация ответных документов — на R2.

## 6. Учётные записи (Active Directory)

- SSO для сотрудников уже реализовано через AD.
- Группы AD, релевантные для «Приёмка+»:
  - `SV-Receiving-Operators` — приёмщики
  - `SV-Receiving-Supervisors` — старшие смены
  - `SV-ERP-Operators` — оператор 1С
  - `SV-Buyers-{Direction}` — закупщики (по направлениям)
  - `SV-Warehouse-Managers` — руководитель склада
  - `SV-Admins-ReceivingPlus` — администраторы модуля

Модуль должен использовать AD для аутентификации и получения групп для авторизации.

## 7. Сетевая инфраструктура

- Между главным офисом и РЦ — VPN-туннель (Kerio), 100 Мбит.
- Внутри РЦ — Wi-Fi UniFi.
- Backend «Приёмка+» будет размещён в собственном ЦОД рядом с 1С.

## 8. Мониторинг и алертинг

- Уже развёрнуты Zabbix и Prometheus.
- «Приёмка+» должен отдавать `/metrics` в Prometheus-формате.

## 9. Ограничения безопасности от IT-директора

- Все данные шифруются at-rest (LUKS на серверах).
- Транспорт — только TLS 1.2+.
- Логи фото — 3 года, потом архив.
- Разрешено использовать open-source, если лицензия не GPL.
