# UX-приоритет пользовательских классов

UX-приоритет — это ранжирование пользовательских классов по степени внимания, которое они получают при проектировании интерфейса

### Итоговая оценка

### Обоснование по классам

**UC-01 Приёмщик (125, №1).** Работает в системе всю смену, каждая ошибка задерживает приёмку и создаёт очередь на разгрузке. Работает на ТСД в холодном складе, часто в перчатках, при шуме — это самые сложные условия из всех классов. Требует максимума UX-внимания.

**UC-03 Оператор 1С (80, №2).** Ежедневная работа с передачей данных и оформлением документов. Ошибка передачи означает искажение учётных данных, поэтому критичность высокая. Несмотря на комфортные офисные условия, требует максимальной UX-поддержки из-за возрастной группы, низкой толерантности к изменениям в привычном рабочем процессе и высокой цены ошибки при работе с бухгалтерскими данными.

**UC-02 Старший смены (64, №3).** Постоянно в системе, принимает решения по эскалациям. Работает на офисном ПК плюс мобильном устройстве при обходе склада. Опыт работы с профильным ПО среднего уровня. Задача - быстрое принятие решений на одном экране.

**UC-04 Закупщик (36, №4).** Подключается только при выходе расхождений за порог. Работает за десктопом в офисе, профильный опыт с 1С и корпоративными системами. Нуждается в качественных уведомлениях и быстром доступе к контексту поставки.

**UC-06 Руководитель склада (12, №5).** Использует систему для аналитики и мониторинга KPI. Работа не требует немедленной реакции, обходные пути есть (можно получить отчёт через оператора). Комфортные условия работы.

**UC-05 Администратор (4, №6).** Разовые настройки, техническая роль. Высокая техграмотность, готов работать с любым интерфейсом. Приоритет минимальный.
